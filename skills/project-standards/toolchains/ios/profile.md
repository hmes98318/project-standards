# iOS Toolchain Profile

## Detection

An Xcode project (`.xcodeproj` or `.xcworkspace`) whose build settings target the iOS SDK (`SDKROOT = iphoneos`), with Swift sources. This platform profile extends the [`swift`](../swift/profile.md) profile: apply that profile in the same variant first, then this profile's additions, and use this profile's Commands instead of the Swift ones.

## Variants

| Variant | Style authority | Summary |
| --- | --- | --- |
| `recommended` | [Swift API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/) and Apple platform conventions | the Swift `recommended` toolchain, warnings as errors and complete concurrency checking for the app's own targets |
| `google` | [Google Swift Style Guide](https://google.github.io/swift/) | the Swift `google` toolchain, warnings as errors and complete concurrency checking for the app's own targets |

## Install

Xcode with Swift 6 or newer. Attach `Standards.xcconfig` to the app and test targets only, never globally or on the command line, because Xcode builds Swift package dependencies with warnings suppressed and a global warnings-as-errors setting conflicts with that. Do not hand-edit `project.pbxproj`:

- When the targets already use an `.xcconfig`, add `#include "Standards.xcconfig"` (with the correct relative path) to it.
- When the project is generated by XcodeGen or Tuist, reference the file from the project specification.
- Otherwise, report in the Completion Report that the user must set it as the targets' base configuration in Xcode (project, Info, Configurations).

When the testing policy requires tests and none exists, setup creates no test target: report that the user must add a unit test target that uses Swift Testing, which ships with Xcode, in Xcode, and add no package dependency.

## Commands

Replace `<scheme>` with the application's main scheme, add `-workspace` or `-project` when the directory contains more than one, and pick an installed simulator for tests from `xcrun simctl list devices available`. Replace `Sources Tests` with the application's Swift source directories.

| Command | Invocation |
| --- | --- |
| `format` | `swift format --in-place --recursive Sources Tests` |
| `lint` | `swift format lint --strict --recursive Sources Tests` |
| `typecheck` | `xcodebuild build -scheme <scheme> -destination 'generic/platform=iOS Simulator' -quiet` |
| `test` | `xcodebuild test -scheme <scheme> -destination 'platform=iOS Simulator,name=<device>,OS=latest' -quiet` |
| `verify` | `swift format lint --strict --recursive Sources Tests && xcodebuild build -scheme <scheme> -destination 'generic/platform=iOS Simulator' -quiet` |

## Style rules

### recommended

- Mark types and functions that touch UI with `@MainActor`, and never block the main thread with synchronous I/O or long computation.
- Declare delegate properties `weak`, and capture `self` weakly in escaping closures that can outlive their owner.
- Keep view state in the view's `@State` or an `@Observable` model (iOS 17 or newer); keep networking, persistence, and business logic out of views and view controllers.
- Store credentials and tokens in the Keychain, never in `UserDefaults`, source files, or property lists.
- Log with `Logger` from `os` instead of `print`, and mark an interpolated value `privacy: .public` only when it holds no personal data.
- Put user-visible text in localized string catalogs, support Dynamic Type, and give interactive elements accessibility labels.

### google

- Mark types and functions that touch UI with `@MainActor`, and never block the main thread with synchronous I/O or long computation.
- Declare delegate properties `weak`, and capture `self` weakly in escaping closures that can outlive their owner.
- Keep view state in the view's `@State` or an `@Observable` model (iOS 17 or newer); keep networking, persistence, and business logic out of views and view controllers.
- Store credentials and tokens in the Keychain, never in `UserDefaults`, source files, or property lists.
- Log with `Logger` from `os` instead of `print`, and mark an interpolated value `privacy: .public` only when it holds no personal data.
- Put user-visible text in localized string catalogs, support Dynamic Type, and give interactive elements accessibility labels.

## Adaptation points

- Projects still on the Swift 5 language mode: keep `SWIFT_STRICT_CONCURRENCY = complete`; under the Swift 6 language mode it is already implied and may stay.
- Projects with Objective-C sources: `GCC_TREAT_WARNINGS_AS_ERRORS` applies to them; keep it.
- Projects that use Swift macros or package plugins: add `-skipMacroValidation` and `-skipPackagePluginValidation` to the `xcodebuild` commands in CI only.
- UIKit apps and apps that support iOS versions before 17: drop the `@Observable` part of the view-state rule.
- Targets with script build phases, such as CocoaPods, SwiftGen, or Crashlytics: `ENABLE_USER_SCRIPT_SANDBOXING = YES` breaks scripts that read or write outside their declared inputs and outputs; declare them, or set it to `NO` for those targets and report it.

## Existing tooling

- SwiftLint or SwiftFormat covers the concerns the Swift profile lists.
- Existing warnings-as-errors build settings in the targets' `.xcconfig` files or build settings cover the compiler-checks concern.
- An existing test framework or runner stays: XCTest and XCUITest suites, and an existing `.xctestplan` used with `-testPlan`.
